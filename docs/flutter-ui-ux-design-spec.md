## 2. 设计目标与产品判断

### 2.1 产品定位

KNcard App 是一个离线优先的移动学习工具，核心任务不是“管理内容”，而是帮助用户在碎片时间内完成以下三件事：

1. 快速知道今天要复习什么。
2. 清楚、舒适地阅读文档和卡片内容。
3. 以低摩擦完成复习，并知道下一次何时复习。

因此，界面优先级必须是：

```text
今日复习任务 > 当前阅读/答题内容 > 操作反馈 > 统计和管理信息 > 次要设置
```

### 2.2 体验目标

| 目标 | 用户感受 | 可验证结果 |
| --- | --- | --- |
| 复习入口明确 | 打开首页就知道下一步做什么 | 首屏可见待复习数量和开始按钮 |
| 答题不中断 | 不因滚动、网络或按钮位置迷路 | 主要操作固定在稳定区域 |
| 信息可扫描 | 列表不需要逐项打开才知道状态 | 条目展示标题、类型、时间和状态 |
| 同步可解释 | 用户知道数据是否安全、是否待上传 | 状态包含文字、时间、数量和重试入口 |
| 只读边界清晰 | 不误以为 App 支持编辑 | 当前阶段隐藏编辑、删除、发布入口 |
| 视觉克制 | 像一个长期使用的工具，而不是宣传页面 | 少用装饰卡片、渐变和大面积插画 |

### 2.3 当前阶段硬约束

本阶段允许的业务写入只有：

- 复习事件。
- FSRS 卡片状态。
- 复习历史。
- 同步队列。
- 用户设置和会话信息。

本阶段必须隐藏或不实现：

- 创建、编辑、删除、移动、重命名文档。
- Markdown 或富文本编辑。
- 创建、编辑、删除卡片。
- 牌组发布、上传、下架和版本提交。
- 协作审核和管理员工作区。

任何页面不得出现看起来像编辑的浮动按钮、铅笔图标、删除菜单或“保存内容”按钮。只读页面可以提供搜索、筛选、排序、复制链接、系统分享等非内容变更操作，但若实际能力尚未接通，应暂不展示。

## 3. 现实产品参考：AnkiDroid

### 3.1 选择理由

本项目以 **AnkiDroid** 作为复习体验的主要现实产品参照，原因如下：

- 产品任务同样围绕牌组、到期卡片、复习队列和记忆评分。
- 用户对 `Again / Hard / Good / Easy` 四档反馈已有成熟认知。
- 其核心界面强调任务、内容和操作，不依赖营销式视觉装饰。
- 它适合离线使用，符合 KNcard 的离线优先方向。

知识库和市场不是 AnkiDroid 的完全对应场景，因此不照搬其页面，而是借鉴其以下方法：

- 让主要任务成为屏幕上最明确的操作。
- 将高频操作放在拇指容易触达的位置。
- 把牌组、卡片数量、到期状态和复习进度作为第一信息层级。
- 用稳定、可预测的操作反馈替代复杂动画。

### 3.2 参考范围与禁止照搬项

| 参考内容 | KNcard 采用方式 |
| --- | --- |
| 牌组驱动的复习入口 | 首页按今日待复习任务组织内容 |
| 到期数量与复习进度 | 首页和学习页展示数量与进度 |
| 四档评分 | 学习页底部固定评分区 |
| 复习后续时间预览 | 每个评分按钮展示下一次复习时间 |
| 工具型信息密度 | 列表避免大面积装饰和过多空白 |
| AnkiDroid 的具体颜色、图标和布局 | 不直接复制，使用 KNcard 自己的设计令牌 |
| 桌面端复杂管理入口 | 移动端当前阶段不迁移编辑和发布功能 |

### 3.3 产品气质

最终视觉应接近“安静、可靠、适合每天打开的学习工具”：

- 不使用渐变 Hero、玻璃拟态或装饰性彩色光球。
- 不把每一个区块都做成漂浮卡片。
- 不使用过大的标题抢占内容空间。
- 使用少量颜色表达任务状态，其他内容回归中性。
- 允许列表信息密度较高，但保证组间距、点击区域和可读性。

## 4. 信息架构与导航

### 4.1 一级导航

底部导航保留五个入口，顺序固定：

| 位置 | 标签 | 图标语义 | 核心任务 |
| --- | --- | --- | --- |
| 1 | 复习 | `school` 或学习类图标 | 开始今日复习、查看统计 |
| 2 | 知识库 | `menu_book` | 找文档、阅读内容 |
| 3 | 卡片 | `style` | 搜索和检查卡片 |
| 4 | 市场 | `storefront` | 浏览和下载牌组 |
| 5 | 我的 | `person` | 账户、设置、同步 |

规则：

- 当前选中项使用主色图标和标签，未选中项使用中性色。
- 底部导航只表达一级导航，不放“同步中”这类动态状态。
- 同步状态在复习首页和“我的”页面出现，不改变导航结构。
- 学习页属于全屏任务流，可以暂时隐藏底部导航，避免误触离开。

### 4.2 路由层级

```text
/auth/login
/auth/register
/(shell)/review
/(shell)/review/study
/(shell)/review/completed
/(shell)/review/history
/(shell)/library
/(shell)/library/document/:documentId
/(shell)/cards
/(shell)/cards/:cardId
/(shell)/market
/(shell)/market/deck/:deckId
/(shell)/settings
/(shell)/settings/sync
/(shell)/settings/review
```

学习页和牌组下载详情页属于高专注任务。进入后应使用明确的返回按钮和系统返回键，不依赖用户点击底部导航切换页面。

## 5. 设计令牌

### 5.1 颜色令牌

建议在 `lib/app/app_theme.dart` 中集中定义 `ColorScheme`，页面内不得散落大量硬编码颜色。

| 令牌 | 建议色值 | 用途 |
| --- | --- | --- |
| `primary` | `#166B63` | 主按钮、选中项、链接、完成状态 |
| `primaryContainer` | `#D7F0EB` | 主任务背景、选中背景、浅色提示 |
| `secondary` | `#C87932` | 待复习、提醒、需要处理的任务 |
| `secondaryContainer` | `#FCE8D3` | 待复习数量背景、提醒区域 |
| `error` | `#B3261E` | 错误、失败、危险操作 |
| `surface` | `#FFFFFF` | 页面内容和主要容器 |
| `surfaceContainerLowest` | `#F7F8F7` | 页面背景 |
| `outline` | `#D5DBD8` | 分隔线、输入框边界 |
| `onSurface` | `#1B1D1C` | 主要文字 |
| `onSurfaceVariant` | `#5D6662` | 次要文字、元数据 |

说明：色值是实现起点，不是不可调整的品牌规范。实现后必须用真机和对比度工具验证，正文和重要操作不能只依赖颜色区分。

### 5.2 尺寸令牌

```text
pageHorizontalPadding = 16dp
pageHorizontalPaddingWide = 20dp
sectionGap = 24dp
itemGap = 12dp
compactGap = 8dp
minimumTapTarget = 48dp
smallRadius = 8dp
mediumRadius = 12dp
largeRadius = 16dp
```

使用规则：

- 页面默认水平内边距为 `16dp`，平板或宽屏内容区域最大宽度建议为 `720dp`。
- 主要区块之间使用 `20-24dp`，同一区块内部使用 `8-12dp`。
- 圆角不超过 `16dp`；普通列表尽量使用 `8dp` 或直角分隔布局。
- 主要按钮高度至少 `48dp`，底部评分按钮高度建议 `52-56dp`。
- 不使用屏幕宽度直接缩放字体，字体大小通过层级和可访问性设置控制。

### 5.3 排版令牌

建议使用系统字体，优先保证中文在 Android 真机上的字形和回退稳定。

| 层级 | 建议字号 | 字重 | 用途 |
| --- | ---: | ---: | --- |
| 页面标题 | 24sp | 700 | 一级页面标题，最多一行 |
| 区块标题 | 18sp | 700 | 今日复习、最近记录等 |
| 卡片标题 | 16sp | 600 | 文档、牌组、卡片标题 |
| 正文 | 15-16sp | 400 | 阅读正文、解析 |
| 辅助文本 | 13sp | 400 | 时间、作者、数量等 |
| 标签文字 | 12sp | 600 | badge、状态标签 |

标题必须真实对应内容层级。卡片内部不能使用页面标题字号；正文不能使用过小字号来强行压缩信息。

## 6. 组件规范

### 6.1 页面骨架

每个一级页面遵循：

```text
Scaffold
  SafeArea
    CustomScrollView / ListView
      页面头部
      页面状态区
      主要内容
      次要内容
```

避免在 `Scaffold` 内嵌套多个独立滚动区域。学习页可以使用一个主体滚动区加一个固定底部操作区；底部操作区不能随内容一起滚走。

### 6.2 SectionHeader

用途：区分页面区块，不把每个区块都包装成 Card。

规格：

- 左侧显示区块标题和可选的数量。
- 右侧只放一个简短动作，例如“查看全部”。
- 右侧动作使用文字或图标+文字，不使用过长按钮。
- 标题与页面主标题的字号明显区分。

建议接口：

```dart
SectionHeader(
  title: '最近复习',
  trailing: TextButton(...),
)
```

### 6.3 StatTile

用于今日复习数量、完成数、连续学习天数等统计。只展示一个主要数值和一个解释标签，不在单个统计块内塞入完整图表。

规格：

- 主要数字至少 `24sp`。
- 标签使用辅助文本。
- 颜色只表达状态，不为每个数字使用不同鲜艳颜色。
- 多个 StatTile 横向排列时，使用稳定宽度或 `Expanded`，避免数字变化导致布局抖动。

### 6.4 StatusBadge

状态 badge 必须同时包含文字和可选图标：

| 状态 | 文案示例 | 图标 |
| --- | --- | --- |
| 已同步 | 已同步 | `cloud_done` |
| 待同步 | 3 项待同步 | `cloud_upload` |
| 同步中 | 同步中 | `sync` |
| 离线 | 离线可用 | `cloud_off` |
| 失败 | 同步失败 | `error_outline` |
| 暂停 | 已暂停 | `pause_circle_outline` |

### 6.5 EmptyState 与 ErrorState

空状态必须告诉用户“为什么为空”和“下一步能做什么”。

结构：

```text
图标
标题
解释文字
主操作（可选）
次操作（可选）
```

禁止只显示“暂无数据”。应区分：

- 尚未同步。
- 当前筛选条件没有结果。
- 今日计划已完成。
- 网络失败但本地没有缓存。

错误状态必须提供可恢复动作，例如“重试”或“查看同步设置”；不可恢复错误要说明联系管理员或重新登录。

### 6.6 搜索与筛选

- 搜索框采用浅色填充或轻边框，默认高度 `48dp`。
- 筛选项不全部铺在页面上，超过两个条件时使用 Bottom Sheet。
- 页面顶部显示筛选摘要，例如“全部牌组 · 到期 · 2 个标签”。
- 清空筛选使用一个明确的图标按钮或短文本按钮。
- 搜索输入应防抖，键盘弹出时页面可滚动，搜索框不被遮挡。

### 6.7 按钮

按钮层级固定为：

1. Filled Button：页面唯一主要动作，例如“开始复习”“下载牌组”。
2. Tonal Button：次要但常用动作，例如“立即同步”。
3. Outlined Button：次要替代动作。
4. Text/Icon Button：导航、清除、更多等低风险动作。

一个页面不应出现两个同等视觉重量的主要 Filled Button。危险操作使用 `error` 色，并始终有确认步骤。

## 7. 页面详细规格

### 7.1 登录页

#### 目标

让用户在最少步骤内完成登录，同时清楚知道连接的是哪个服务器。

#### 推荐布局

```text
SafeArea
  顶部留白
  品牌名 KNcard
  一句短说明：在碎片时间复习重要知识
  服务器地址输入框
  用户名输入框
  密码输入框 + 显示/隐藏密码
  记住账号开关
  登录主按钮
  注册入口
  错误/网络状态区
```

#### 交互要求

- 服务器地址支持默认值，但保留修改入口。
- 点击登录后主按钮进入 loading，禁止重复提交。
- 键盘出现时使用 `SingleChildScrollView` 或等效方案，按钮不可被遮挡。
- 错误至少区分：地址不可达、超时、账号密码错误、账户停用、令牌失效。
- 密码进入安全存储；页面文案不能暴露令牌内容。

#### 禁止项

- 不使用大面积插画、营销卡片或复杂渐变。
- 不把服务器地址隐藏到难以发现的设置页。
- 不只用 SnackBar 显示登录失败，用户应能在表单附近看到原因。

### 7.2 复习首页

#### 目标

用户打开后五秒内知道今日任务，并能直接开始复习。

#### 首屏布局

```text
AppBar
  问候/日期
  同步状态 badge

今日复习主任务区
  今日待复习：24
  已完成：8 / 24
  完成率进度条
  [开始复习]

统计条
  新卡 6 | 到期 18 | 连续 5 天

最近复习
  牌组名称 + 完成数量 + 时间

查看更多统计
```

主任务区可以是一个轻量容器，但不能套在多个嵌套卡片中。主按钮宽度建议填满可用区域，点击区域至少 `48dp`。

#### 状态分支

| 状态 | 主标题 | 主动作 |
| --- | --- | --- |
| 有待复习 | 今日复习 | 开始复习 |
| 今日完成 | 今日计划已完成 | 查看历史/浏览卡片 |
| 无缓存 | 等待首次同步 | 立即同步 |
| 离线有缓存 | 离线可继续复习 | 开始离线复习 |
| 同步失败 | 内容可能不是最新 | 重试同步 |

#### 统计原则

- 首屏只放最重要的三个统计：新卡、到期、连续天数。
- 热力图、趋势图和详细 FSRS 分布放入“统计/历史”页面，不挤压主任务。
- 最近复习记录最多展示三项。

### 7.3 学习页

#### 目标

把注意力集中在当前卡片，减少滚动和误触，保证“答题反馈”和“记忆评分”是两个清楚的阶段。

#### 布局

```text
Scaffold
  顶部固定栏
    退出
    3 / 20
    牌组名称
  进度条
  主体滚动区
    卡片类型 badge
    题干
    选项或速记内容
    答题反馈（提交后）
    解析（有内容才显示）
  底部固定区
    Again | Hard | Good | Easy
    每个按钮显示下一次复习时间
```

#### 答题阶段

- 单选题：一次只能选中一个选项。
- 多选题：至少选择一个选项后才能提交。
- 判断题：使用两个清晰的选项，不依赖文字颜色区分。
- 速记词条：先展示内容，再提供熟悉、模糊、没印象的反馈。
- 提交后锁定选择，避免用户在反馈阶段继续改变答案。

#### 反馈阶段

同时显示：

- 用户选择。
- 正确答案。
- “回答正确”或“回答错误”文字。
- 解析内容（如果存在）。

正确与错误应使用图标、文字和边框组合；不能只把背景改成绿色或红色。

#### 评分阶段

评分按钮建议采用四等分横向排列，窄屏下允许两行两列，但按钮尺寸必须稳定。每个按钮包含：

```text
Again
10 分钟
```

时间预览来自 FSRS 计算结果；如果计算失败或数据不可用，显示“稍后复习”而不是伪造时间。

评分写入必须是本地事务：卡片状态、复习事件和同步队列要么全部成功，要么全部回滚。网络失败不能阻止本地评分。

### 7.4 复习完成页

布局：

```text
完成图标
复习完成
本次完成 20 张 · 用时 12 分钟

评分分布
Again 2 | Hard 4 | Good 11 | Easy 3

下一次复习
明天预计 8 张

[返回复习首页]
[查看复习历史]
```

状态文案应避免夸张庆祝动画，保持学习工具的克制感。没有完成任何卡片时，改为解释原因，不显示“完成”错觉。

### 7.5 知识库列表与文档详情

#### 列表

顶部：页面标题、文档数量、搜索按钮、筛选按钮。搜索展开后才占用一整行。

文档条目展示：

- 标题，最多两行。
- 文件夹路径或分类。
- 更新时间。
- 文档类型图标。
- 已读/最近阅读状态（如果数据层支持）。

条目使用轻量分隔线或低层级容器，不要每一条都堆叠厚重 Card。

#### 详情

- 顶部显示标题、文件夹、更新时间。
- 正文限制最大阅读宽度，平板上不拉满整个屏幕。
- Markdown 标题层级、段落、列表、引用、代码、表格、链接保持一致的间距。
- 代码块允许横向滚动，正文不被长代码撑破。
- 外部链接点击前给出清晰行为，不自动打开未知协议。
- 当前阶段保持只读，不显示编辑、删除和浮动铅笔按钮。

### 7.6 卡片库与卡片详情

#### 列表

顶部优先展示搜索和当前筛选摘要，筛选条件通过 Bottom Sheet 打开。排序入口支持：

- 下次复习时间。
- 最近复习时间。
- 复习次数。
- 创建时间。

卡片条目展示：

- 类型 badge：单选、多选、判断、速记。
- 题干摘要，两行截断。
- 牌组名称。
- 标签。
- 复习状态：新卡、学习中、复习中、暂停。
- 下次复习时间。

#### 详情

使用只读内容分区：题干、选项、答案、解析、FSRS 信息。不要把字段渲染成像表单的可编辑输入框。

### 7.7 市场与牌组详情

#### 市场列表

牌组条目展示：

- 标题和作者。
- 分类和标签。
- 卡片数量。
- 下载量。
- 版本和更新时间。
- 已下载/有更新/未下载状态。

#### 详情与下载

详情页底部固定下载区：

```text
未下载：[下载牌组]
已下载：[打开牌组] [检查更新]
下载中：[进度条] 校验中...
失败：[重新下载]
```

下载流程状态必须按“下载中 → 校验中 → 导入中 → 完成/失败”更新，失败时显示可理解原因，例如网络中断、文件校验失败或版本不兼容。

### 7.8 我的与设置

按用户任务分组，而不是按内部技术模块分组：

1. 账户：账号、昵称、退出登录。
2. 本地内容：缓存大小、已下载牌组、清理缓存。
3. 复习设置：每日上限、新卡上限、顺序、默认牌组。
4. 同步：在线状态、最后同步、待同步数量、失败原因、立即同步。
5. 关于与诊断：版本、服务器地址、日志诊断入口。
6. 危险操作：清除本地数据，必须独立分区并二次确认。

设置项使用清晰的标题、解释文字和当前值。不要把服务器地址、数据库状态、权限 JSON 等内部字段直接堆在用户面板上。

## 8. 状态设计与文案规范

### 8.1 全局状态模型

页面至少考虑以下状态：

```text
initial
loading
loaded
empty
offline-with-cache
offline-without-cache
refreshing
error-retryable
error-auth-required
```

状态切换不能只通过控制台日志表达，必须在页面上给用户可理解的反馈。

### 8.2 同步状态

| 内部状态 | 用户文案 | 是否阻塞阅读/复习 |
| --- | --- | --- |
| `idle` | 已同步 | 否 |
| `syncing` | 正在同步 | 否，局部显示进度 |
| `pending` | 3 项待同步 | 否 |
| `offline` | 离线，已缓存内容可用 | 否 |
| `failed` | 同步失败，可重试 | 否，除非没有本地数据 |
| `authRequired` | 请重新登录以同步 | 不阻塞本地内容 |

### 8.3 文案规则

- 先说状态，再说影响，再给动作。
- 使用“无法加载文档，请重试”，不要使用“发生未知错误”。
- 使用“当前筛选条件下没有卡片”，不要使用“暂无数据”。
- 使用“复习结果已保存，等待网络恢复后同步”，让离线行为可解释。
- 操作按钮使用动词：开始复习、立即同步、重试、打开牌组。

## 9. 可访问性与移动端适配

### 9.1 点击与手势

- 所有可点击目标至少 `48dp x 48dp`。
- 图标按钮必须设置语义标签。
- 不把滑动作为唯一操作方式；关键功能必须有按钮入口。
- 系统返回键返回上一级；学习中退出需要确认，避免误丢当前进度。

### 9.2 字体与布局

- 支持系统字体放大，不得出现按钮文字裁切。
- 题干、选项和解析可以换行，不能依赖固定高度硬裁切。
- 长标题最多两行，超出后用省略号，但详情页显示完整标题。
- 窄屏下评分按钮改为两行两列，不压缩到无法点击。
- 键盘弹出时登录和搜索页面必须保持可操作。

### 9.3 颜色与状态

- 正确/错误必须配合图标和文字。
- 离线/同步失败必须配合状态文案。
- 文字与背景对比度满足移动端可读性要求。
- 不使用红绿色作为唯一的可用/不可用区分。

## 10. Flutter 实施建议

### 10.1 文件组织

建议新增基础组件：

```text
lib/app/app_theme.dart
lib/core/widgets/section_header.dart
lib/core/widgets/stat_tile.dart
lib/core/widgets/status_badge.dart
lib/core/widgets/empty_state.dart
lib/core/widgets/error_state.dart
lib/core/widgets/sync_status_bar.dart
lib/core/widgets/app_scaffold.dart
lib/core/widgets/primary_action_button.dart
```

建议页面内部按以下顺序拆分：

```text
page.dart
  页面状态监听
  页面骨架
  头部区块
  状态区块
  业务区块
  空/错误分支
  私有展示组件
```

### 10.2 状态管理边界

- Riverpod Provider 管理加载、刷新、错误、空数据和提交状态。
- Widget 只负责展示状态和触发意图，不直接操作数据库。
- 复习评分由 Controller 完成本地事务，再更新页面队列。
- 同步状态由统一的 `SyncController` 提供，页面不得各自定义一套在线/离线判断。

### 10.3 主题实现

`AppTheme` 至少统一以下内容：

- `ColorScheme`。
- `TextTheme`。
- `CardThemeData`。
- `InputDecorationTheme`。
- `FilledButtonThemeData`。
- `OutlinedButtonThemeData`。
- `NavigationBarThemeData`。
- `BottomSheetThemeData`。
- `SnackBarThemeData`。

页面层只在确有语义差异时提供局部样式，禁止为了单个页面复制整套颜色和尺寸。

### 10.4 动画边界

只使用帮助理解状态变化的短动画：

- 页面局部加载淡入。
- 复习进度更新。
- 下载进度变化。
- 展开/收起筛选。

不使用自动循环动画、强烈弹跳和长时间转场。离线、弱网和低端手机环境下，动画不应阻塞交互。

## 14. 设计决策总结

本次优化不追求“页面更花”，而是让 KNcard 更像一个用户愿意每天打开的现实学习 App：

- 复习首页借鉴 AnkiDroid 的任务驱动方式，把到期复习和开始动作放在首屏中心。
- 学习页采用稳定顶部进度和固定底部评分区，减少滚动和误触。
- 知识库采用阅读工具的排版逻辑，优先保证 Markdown、代码和长文本的舒适性。
- 卡片库和市场提高信息密度，让用户在列表中就能做判断。
- 设置按用户问题分组，同步状态变成可解释、可恢复的功能。
- 统一主题和基础组件，避免每个页面各自发展成不同的视觉系统。
- 保持当前阶段的只读边界，所有内容编辑能力留待独立需求和交互设计完成后再做。

建议开发顺序固定为：**阶段 A 统一基础样式 → 阶段 B 复习主流程 → 阶段 C 知识库与卡片库 → 阶段 D 市场与设置 → 阶段 E 真机验收**。
